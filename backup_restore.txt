1. Conectando o pgAdmin ao seu Banco de Dados do Render
Antes de tudo, você precisa ter o pgAdmin instalado em sua máquina. Se ainda não o tem, pode baixá-lo em pgadmin.org.
Obtenha a External Database URL do Render:
Acesse o painel do Render e navegue até o seu serviço de PostgreSQL.
Procure pela External Database URL. Ela terá um formato similar a: postgresql://USUARIO:SENHA@HOST:PORTA/NOME_DO_BANCO
Anote ou copie cada parte dessa URL: USUARIO, SENHA, HOST, PORTA e NOME_DO_BANCO.
Abra o pgAdmin e Adicione um Novo Servidor:
Inicie o pgAdmin.
No painel esquerdo, clique com o botão direito em Servers e selecione Register > Server....
Preencha os Detalhes da Conexão:
Guia General:
Name: Dê um nome amigável para a sua conexão (ex: Render_Hering_DB).
Guia Connection:
Host name/address: Cole o HOST que você obteve da URL do Render.
Port: Cole a PORTA (geralmente 5432).
Maintenance database: Digite o NOME_DO_BANCO (ex: nome_do_seu_banco).
Username: Cole o USUARIO.
Password: Cole a SENHA.
Clique em Save.
Se tudo estiver correto, o pgAdmin se conectará ao seu banco de dados no Render e você poderá vê-lo listado sob Servers.
2. Realizando o Backup (Exportação) no pgAdmin
Com a conexão estabelecida, agora você pode exportar seus dados:
Selecione o Banco de Dados:
No pgAdmin, expanda a árvore de Servers > Render_Hering_DB (ou o nome que você deu) > Databases.
Clique com o botão direito no NOME_DO_BANCO que você deseja fazer backup e selecione Backup....
Configure as Opções de Backup:
Guia General:
Filename: Clique no ícone de pasta para escolher onde salvar o arquivo de backup em seu computador e dê um nome (ex: backup_hering_db_YYYYMMDD.sql).
Format: Recomendo escolher Custom ou Tar. Esses formatos são mais flexíveis para restauração e podem ser mais compactos. O formato Plain gera um arquivo .sql que é fácil de ler, mas pode ser menos eficiente para grandes bancos de dados.
Guia Options:
Do not save owner: Marque esta opção para evitar problemas de permissão ao restaurar em um novo servidor.
Do not save privileges: Marque esta opção pelo mesmo motivo acima.
Pre-data, Data, Post-data: Certifique-se de que todos estejam marcados para incluir a estrutura do banco de dados e os dados.
Você pode explorar outras opções, mas as configurações padrão geralmente são suficientes para um backup completo.
Inicie o Backup:
Clique no botão Backup.
O pgAdmin mostrará uma janela de progresso. Ao finalizar, você terá um arquivo de backup salvo no local que você especificou.
3. Dicas para Restauração e Manutenção
Restauração: Para restaurar, você usaria a opção Restore... no pgAdmin, apontando para o arquivo de backup que você criou. É importante que o banco de dados de destino esteja vazio ou que você tenha certeza de que deseja sobrescrever os dados existentes.
Frequência: Faça backups regularmente, especialmente antes de grandes mudanças ou quando novos dados importantes forem adicionados.
Migração: Antes do prazo de 90 dias, você pode restaurar este backup em um novo serviço de PostgreSQL (seja no Render, em outro provedor ou localmente) para continuar usando seu aplicativo sem interrupções.
